## 9. Betriebsstruktur — ✅ vorbereitet

KISS-Betriebsmodell für dieses Projekt:

### Besitz / Verantwortlichkeit
- Domaininhaber: Kevin / KS-Innenausbau
- Website-Code: privates GitHub-Repository unter KISS-Verwaltung
- Produktionshosting: später KISS-verwaltetes Hostingkonto
- Kunden-E-Mail: bestehendes Kundensystem; keine Migration ohne separaten Auftrag
- Search Console / Google Business: Kunde bleibt Eigentümer, KISS erhält Manager-/Arbeitszugriff

### Sicherheitsstandard
- keine Passwörter im Repo
- Passwortmanager für KISS-Zugänge
- 2FA überall, wo möglich
- getrennte Kundenaccounts/Zugänge
- minimale Berechtigungen
- kein Teilen von Masterpasswörtern per Chat/Mail

### Betriebsstandard
- Git als Source of Truth für Website-Code
- Produktion nur aus freigegebenem `main`
- dokumentierter Release
- Rollback-Möglichkeit
- Uptime-Monitoring
- SSL-Überwachung
- Formular-Zustellung regelmäßig prüfen
- Backup-/Restore-Prozess dokumentieren
- Kundenakte mit Domain, DNS, Hosting, Mail, Google-Zugriffen, Vertrag und Care-Status
